现状痛点： 我们在前面看到的提示词里写了大量极其严苛的防御性指令：

“工作区、仓库HEAD与线上入口分别核对”、“不以单一作用域未命中代表不存在”、“按用户原入口复测，说明已改、已测、已加载或仍缺的验证”…… 这导致模型产生了“强迫症式的穷举心理”： 即使它在第 3 步通过 fix_need.md 和源码已经确认“这个问题已经被先前的 commit 修复了”，它也不敢退出，因为提示词逼着它去核对进程 PID、去核对测试用例、去查 git log。

主流 Agent 的做法： 主流 Agent 的规划原则是假设证伪即停（Early Exit）：
排查前先建立假设（“该问题是否已被修复？”）；
一旦取得关键决定性证据（如发现修复提交已存在且源码已对齐），立即触发短路退出（Short-circuit Termination），直接向用户交卷，坚决禁止“为了证明自己严谨而继续去测无关模块”
